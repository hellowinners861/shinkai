# SHINKAI — 自動潜航縦切り設計

- Status: Ultra承認済み
- Last updated: 2026-08-12
- Scope: 自動潜航、深度更新、通常燃料消費、海中背景スクロール

## 1. 目的

「潜航を開始」後、調査艇が深海へ進んでいることを、動く海中背景、増える深度、減る燃料の3つで直ちに理解できる状態にする。今回、生物、岩、衝突、回復アイテム、スコア、正式な結果画面は実装しない。

## 2. 進行仕様

| 項目 | 値 |
| --- | ---: |
| 開始深度 | 0m |
| 目標深度 | 6,000m |
| 自動潜航速度 | 25m/秒 |
| 開始／最大燃料 | 100 |
| 通常燃料消費 | 0.18/秒 |
| 想定到達時間 | 240秒 |
| 通常到達時の燃料 | 約56.8 |
| 1フレームで反映する最大時間 | 0.25秒 |

- GameScene開始直後から自動潜航を開始する。操舵入力の有無に依存しない。
- プレイヤーの艇は固定カメラ内を上下左右へ従来どおり移動できる。自動潜航は艇の画面Y座標を強制移動せず、世界が上方向へ流れる表現にする。
- 有効な経過秒ごとに `depth += 25 * seconds`、`fuel -= 0.18 * seconds` とする。
- 深度は0〜6,000m、燃料は0〜100へclampする。負値、NaN、無限値の経過時間は進行させない。
- 長いフレーム、復帰直後、デバッガ停止後の飛びを防ぐため、GameSceneが1回のupdateへ渡す時間は最大0.25秒とする。
- ポーズ中、ライフサイクル停止中、横向き案内中、非表示タブ中は、深度、燃料、背景のすべてを停止する。復帰時に停止時間を追いつき計算しない。
- 6,000m到達時は状態を`cleared`として進行と背景を停止し、既存の右下状態表示を`TARGET REACHED`へ更新して日本語ARIA通知を1回だけ行う。正式なResultSceneへの遷移は次タスクへ延期する。
- 燃料0時は状態を`depleted`として同様に停止し、状態表示を`FUEL EMPTY`へ更新して日本語ARIA通知を1回だけ行う。通常消費だけでは目標前に0にならないが、後続の衝突実装に備える。
- 同じ更新で燃料0と目標到達が同時に成立する場合、クリア条件が燃料1以上であるため`depleted`を優先する。

## 3. 状態モデルと純粋ロジック

新規 `src/game/diveProgression.ts` に初期状態生成、経過時間による更新、clamp、終端判定をPhaser／DOMに依存しない純粋関数として置く。

```ts
type DiveStatus = 'descending' | 'cleared' | 'depleted';

interface DiveProgressionState {
  depthM: number;
  fuel: number;
  elapsedSeconds: number;
  status: DiveStatus;
}
```

- 速度、目標、燃料値はexportした定数またはreadonly設定へ集約し、GameSceneへ数値を重複記述しない。
- 終端状態へ入った後の更新は同じ状態値を維持する。
- 将来の衝突／回復から燃料を更新できる構造にしてよいが、今回はその処理や公開APIを追加しない。

## 4. HUD表示

- 深度は整数切り捨てで最低4桁ゼロ埋めし、`0000 m`、`0025 m`、`1000 m`のように表示する。4桁を超える値は切り捨てない。
- 燃料は小数1桁の`100.0%`形式とし、開始後1秒以内に減少が視認できるようにする。
- 燃料ゲージの幅と`aria-valuenow`を同じ燃料値へ同期する。値は色だけで表現しない。
- 右下状態表示は潜航中に`DESCENDING`と`AUTO / 25 M/S`を表示する。320px幅では既存CSS方針どおり非表示でもよいが、深度と燃料は必ず見える。
- DOM更新は表示値が変わったときだけ行い、不要な毎フレーム書き換えを避ける。

## 5. 海中背景スクロール

- 海中の浮遊物（marine snow）をPhaserの円または短い矩形だけで18〜24個描く。画像、実在生物、外部素材、生成画像を使わない。
- 少なくとも遠景と近景の2層を持ち、遠景は毎秒10〜16px、近景は毎秒28〜40pxで上へ流す。配置と速度は決定的な固定パターンとし、テスト再現性を保つ。
- 上端のテレメトリー領域を通過した要素は下端へ循環させる。生成・破棄を毎周行わず、同じGameObjectを再利用する。
- 装飾alphaは遠景0.08〜0.16、近景0.12〜0.22とし、艇や将来の生物を隠さない。
- ソナー同心円、照準線、深度目盛は計器として固定し、marine snowだけを世界スクロールとして動かす。
- `prefers-reduced-motion: reduce`ではmarine snowの移動を停止する。深度／燃料更新と`DESCENDING`表示は継続し、ゲーム状態は変えない。

## 7. テストと受け入れ基準

- 純粋ロジックで、1秒後が深度25m・燃料99.82、240秒後が深度6,000m・燃料約56.8・`cleared`になる。
- 異常な経過時間、clamp、終端後不変、燃料0優先をユニットテストする。
- 公開／ローカル画面で開始2秒後に深度が0より大きく燃料が100未満となる。
- 時間を空けた2枚の観察でmarine snowが上へ移動し、艇と固定計器は自動潜航だけでは移動しない。
- ポーズ中に1秒以上待っても深度と燃料が変わらず、再開後に再び変化する。
- 320×568で深度`0000 m`相当と燃料`100.0%`相当がHUD内に収まり、停止・音声ボタンと重ならない。
- 既存のタッチ／キーボード移動、ポーズ、音声設定、横向き案内、非表示時停止、明示復帰が維持される。
- `npm run typecheck`、`npm test`、`npm run build`が成功し、ブラウザコンソールエラーがない。
- commit／pushはLuna Maxが行わない。
