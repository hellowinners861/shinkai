# SHINKAI — 能動調査ループ V2 設計

- Status: Ultra承認済み
- Last updated: 2026-08-18
- Scope: 能動スキャン、深度別危険ウェーブ、スコア内訳、新発見結果、自己ベスト
- Target: スマートフォン縦画面 450 × 800、1潜航約4分

## 1. 目的

現在の「中央で無操作でもクリアでき、生物へ偶然接触して得点できる」状態を解消し、次の判断を4分間繰り返すゲームへ更新する。

> 未知の生物を追って観測を完了するか、安全航路を守って燃料を残すか。

本変更後も操作は左下の操舵環または既存キーボードだけとする。スキャン用の追加ボタン、長押し、複数指操作は追加しない。

## 2. 今回の範囲

実装するもの:

1. 接触獲得を廃止し、近距離で一定時間追従する能動スキャンへ置き換える。
2. 岩を深度帯別のウェーブへ置き換え、無操作ではクリアできないが必ず回避可能な難易度曲線を作る。
3. 生物得点、初発見、到達深度、残燃料を分けて最終スコアへ合算する。
4. 結果画面へ今回の新発見一覧、得点内訳、自己ベストを表示する。
5. スマートフォン実触とスクリーンショットによるUltraデザイン評価を行う。

今回実装しないもの:

- クジラ、ダイオウイカ等の大型生物セットピース
- 潜航前ミッション、研究ランク、通貨、強化ツリー
- 全カテゴリ固有の新しい移動AI
- 新規写真、外部素材、音源、生成画像
- カタログ分類、写真manifest、既存149種アイコンの変更

これらは本スライスの実触評価後に別設計とする。

## 3. 能動スキャン

### 3.1 発見と観測データ獲得

- 生物の発見は既存どおり、艇と生物の中心距離が既存探知条件内へ入った時点で成立し、図鑑へ即時保存する。
- 観測データ獲得は物理接触では成立しない。艇と生物の中心距離が96論理px以下の間だけスキャンを進める。
- 物理接触しても生物は燃料ダメージ、押し戻し、即時獲得を発生させない。
- 同時に複数の生物が範囲内へ入った場合、未完了かつ中心距離が最短の個体を1体だけアクティブターゲットとする。同距離はspawn sequenceが早い個体を優先する。
- 各個体は独立したスキャン進捗を持つ。アクティブターゲットだけが進み、それ以外の未完了進捗は実時間1秒につき0.75秒ぶん減衰する。0未満にはしない。
- 必要時間はレア度別に次とする。

| rarity | 必要時間 |
| --- | ---: |
| common | 0.70秒 |
| uncommon | 0.85秒 |
| rare | 1.05秒 |
| very_rare | 1.30秒 |
| legendary | 1.60秒 |

- 必要時間へ到達した個体は1回だけ観測完了となる。既存の獲得回数を1増やし、得点を加え、画面から除去する。
- 1個体から複数回得点しない。別潜航または別spawn個体の同種は再スキャンできる。

### 3.2 NEWと表示優先順位

- 遭遇直前の永続図鑑に存在しない種だけを今回の新発見とする。
- 初発見時の表示は既存どおり NEW! / <display name> とする。
- 同一フレームで初発見とスキャン完了が成立した場合、見た目はNEWを優先し、通常の完了表示で上書きしない。得点と獲得保存は失わない。
- 既発見種の完了表示は SCAN COMPLETE / +<score delta> とする。
- 発見と獲得のARIA通知は意味を分け、同じ文を重複通知しない。

### 3.3 スキャン表示

- 生物の周囲へ円、ハロー、リング、名前ラベル、進捗輪を描かない。
- アクティブターゲット中だけ、艇から対象へ1pxの低不透明度ソナー線を描く。色は既存ソナー色、alphaは0.45以下とする。
- HUDのテレメトリー直下へ高さ28〜34pxの細いSCANレールを置く。対象がない場合はhiddenにする。
- レールはSCAN、対象表示名、0〜100%のバーを持つ。320px幅では対象名を省略できるが、SCANと進捗は残す。
- HTML progressbar相当のARIA値を更新し、色だけで進捗を伝えない。
- reduced-motionでも進捗、線、文言は表示し、脈動や点滅だけを止める。

## 4. 深度別危険ウェーブ

### 4.1 深度帯

| band | 深度 | 役割 | ウェーブ間隔 | 岩数の目安 |
| --- | ---: | --- | ---: | ---: |
| 1 | 0〜999m | 導入 | 6.0秒 | 1 |
| 2 | 1,000〜2,499m | 判断開始 | 5.5秒 | 1〜2 |
| 3 | 2,500〜3,999m | 継続回避 | 5.0秒 | 2〜3 |
| 4 | 4,000〜6,000m | 最終圧力 | 4.5秒 | 3 |

- 岩は単体の固定5レーン巡回ではなく、ウェーブ単位で同時または0.65秒差で生成する。
- 各ウェーブは5レーンのうち最低1レーン、band 1〜2では最低2レーンを安全路として残す。
- 連続ウェーブの安全路は同じレーンへ固定せず、最低でも2ウェーブに1回は移動を要求する。
- centerレーンを意図的に塞ぐウェーブを各深度帯に含める。
- 生成は決定的かつテスト可能にし、フレームレートで順序が変わらないようにする。
- 同一ウェーブの岩同士、回復、生物のspawn位置は重ねない。
- 操舵環に隠れるレーンは、危険がプレイヤー到達線へ来る2.5秒以上前に見える警告目盛を表示する。
- 警告は短い線とHAZARD状態で伝え、点滅は1秒3回未満とする。

### 4.2 回復

- 回復量は既存どおり+25、最大100とする。
- 初回は15秒、以後36秒間隔を基準とする。
- 出現レーンはleftInner、rightInner、leftOuter、rightOuterを循環し、centerには出さない。
- 同時刻の危険ウェーブと重なる場合は最大2秒まで後ろへずらし、それでも安全配置できない場合だけその回を見送る。
- 通常消費と完全回避だけでも燃料56.8前後でクリア可能な既存値を維持し、回復は失敗救済と危険を冒す選択肢にする。

### 4.3 難易度の合格条件

- 中央初期位置のまま入力0で進む決定的シミュレーションは、2,500〜4,500mの間で燃料0になる。
- 全ウェーブに幾何学的に通過可能な安全路がある。
- band 1では初見プレイヤーが危険を認識してから回避できる時間を3秒以上確保する。
- 基本的な左右移動だけで6,000mへ到達可能である。
- 深度帯が変わった際は右下状態にZONE 1〜ZONE 4を併記し、初回だけ短い帯域名を通知する。

## 5. スコア

### 5.1 潜航中

- species base scoreは既存カタログの10、25、50、75、100を使う。
- 初発見ボーナスはその種のbase scoreと同額とする。初回スキャンの合計はbaseの2倍になる。
- clean scan streakはスキャン完了ごとに1増え、岩ダメージで0へ戻る。
- streak倍率は 1 + min(max(streak - 1, 0), 4) × 0.25 とし、最大2.0倍とする。
- scan scoreは round(base score × streak倍率)。初発見ボーナスには倍率を掛けない。
- HUDのSCOREはscan score累計と初発見ボーナス累計の合計を表示する。深度・燃料ボーナスは結果確定時だけ加える。

### 5.2 結果確定

- depth bonusは floor(reachedDepthM / 10)。6,000mで600点。
- fuel bonusは floor(remainingFuel × 10)。最大1,000点。
- final scoreは scan score total + first discovery bonus total + depth bonus + fuel bonus。
- 失敗時も到達深度と残燃料に基づいて計算する。燃料0ならfuel bonusは0。
- すべて非負整数とし、NaN、Infinity、負値を0へ正規化する。

## 6. 結果と永続進捗

### 6.1 結果画面

- 最上部に最終スコアと、今回が自己ベストならNEW BESTを表示する。
- 得点内訳はSCAN DATA、NEW SPECIES、DEPTH、FUELの4項目を表示する。
- 到達深度、残燃料、経過時間、スキャン完了数は維持する。
- 「発見数」は今回の永続図鑑へ新規追加された種数を意味し、既発見種の再検知を含めない。
- 今回の新発見をsource_catalog_id、表示名、学名、categoryで結果snapshotへ渡し、結果画面にアイコン付きで全件表示する。
- 新発見0件では空欄にせず「今回の新発見はありません」と表示する。
- 結果が縦画面を超える場合、結果パネル内部をスクロール可能にし、再潜航・図鑑・タイトルの操作を失わない。

### 6.2 自己ベスト

- 新規localStorageキー shinkai.runProgress、version 1を使う。
- 保存項目は diveCount、clearCount、bestScore、bestDepthM とする。
- 結果確定時に1回だけ更新する。再描画、向き変更、図鑑往復で重複加算しない。
- 破損JSON、未知version、負値、非有限値は安全な初期値へ戻す。
- アカウント、クラウド、ランキング、外部通信は追加しない。

## 7. 技術責務

- スキャン進行・ターゲット選択はPhaser非依存の純粋ロジックへ置く。
- 深度帯、ウェーブ予定、安全路の不変条件はPhaser非依存の純粋ロジックへ置く。
- 得点と結果内訳は純粋ロジックへ置く。
- run progressの読込・正規化・更新はlocalStorageアダプタから分離してテスト可能にする。
- GameSceneはGameObject生成、座標同期、描画、DOM通知を担当する。
- ResultSceneは受け取った不変snapshotの表示だけを担当する。
- 既存カタログJSON、写真asset、manifest、ピクセルアイコン定義は変更しない。

## 9. Ultra実触評価

最終実装後、Ultra担当が公開候補ビルドを390×844相当で実際に操作し、最低1回は以下を確認する。

1. スティックだけでスキャン開始、維持、完了が理解できる。
2. 生物周囲に円がなく、ターゲット線とHUDだけで対象を追える。
3. 無操作では危険だが、警告を見て移動すれば不公平感なく回避できる。
4. 深度帯の変化と後半の圧力上昇を体感できる。
5. 結果で新発見と得点理由が理解でき、再潜航したくなる。
6. タイトル、潜航中、結果の最低3枚のスクリーンショットを取得する。必要ならスキャン中と危険ウェーブ中を追加する。

重大な可読性、操作性、公平性の問題が見つかった場合は公開せず、設計範囲内の修正をLuna Maxへ戻す。

## 10. 完成条件

- 無操作中央シミュレーションが2,500〜4,500mで失敗する。
- 能動スキャン以外では生物得点と獲得回数が増えない。
- 全ウェーブに安全路があり、スマホ操作で6,000mクリア可能である。
- NEW優先、スキャン完了、streak、岩リセット、得点内訳がテストされる。
- 結果画面に新発見一覧と自己ベストが表示され、進捗更新が1潜航1回である。
- 320×568、390×844、430×932で主要UIが操作可能である。
- 既存149種カタログ、写真4点、出典、ライセンス、図鑑進捗を壊さない。
- typecheck、全テスト、asset check、production build、git diff --checkが成功する。
- Ultraの実触・スクリーンショット評価に合格する。
