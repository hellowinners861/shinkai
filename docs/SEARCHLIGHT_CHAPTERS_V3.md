# SHINKAI — サーチライト調査・4章・大型遭遇 V3 設計

- Status: Ultra承認済み
- Last updated: 2026-08-19
- Scope: 右スティック式サーチライト、深度4章、生物カテゴリ行動、大型生物イベント
- Target: スマートフォン縦画面 320 × 568〜430 × 932、論理解像度450 × 800
- Supersedes: `GAMEPLAY_LOOP_V2.md` の近距離スキャン、即時発見、汎用生物移動、ZONE表示

## 1. 目的

艇へ近づくだけで進むスキャンを廃止し、左手で艇を操縦しながら右手で光を向ける「探す・捉える・避ける」二軸の調査ゲームへ更新する。同時に、既存の4深度帯を名前と環境変化を持つ4章へ昇格し、生物カテゴリを見ただけで動きの予測が立つようにする。大型生物は通常spawnから分離し、1潜航に最大1回のセットピースとして扱う。

> 左手で生還経路を選び、右手で暗闇の生命を光の中へ捉える。

## 2. 両手操作

- 左下の既存スティックは艇の上下左右移動専用とする。
- 右下へ直径128 CSS pxのLIGHTスティックを追加する。右スティックの方向を希望照射方向とし、ライトは最大240度/秒で滑らかに追従する。
- 右スティックを離しても最後の照射角度を保持する。初期角度は艇の右向き0度とする。
- 左右のスティックはポインタIDを独立管理し、非primaryを含む2本の指を同時に受け付ける。
- `pointerup`、`pointercancel`、画面非表示、blur、ポーズではつまみを中央へ戻すが、通常のpointerupでは照射角度自体を戻さない。ライフサイクル停止・Scene終了時だけ安全な0度へ初期化する。
- PCはWASD／矢印で移動、IJKLで照射方向を指定する。IJKLを離しても最後の角度を保持する。
- 右下の既存DESCENDING表示は両スティックより上へ移す。
- 衝突時の赤フラッシュと画面揺れから、左右両方のスティックを除外する。

## 3. サーチライト識別

### 3.1 光の判定

- 光は艇から始まる長さ260論理px、全角36度（半角18度）の円錐とする。
- 判定は艇と対象の中心距離、照射角との差、有限値を純粋関数で評価する。物理接触や艇からの単純距離だけでは進捗しない。
- 円錐内に複数いる場合は、中心線との角度差が小さい個体、距離が近い個体、spawn sequenceが早い個体の順に1体を選ぶ。
- 選択中の個体だけ既存レア度別時間で識別が進む。光から外れた未完了進捗は実時間1秒につき0.75秒減衰する。
- 通常生物の必要時間はV2の0.70／0.85／1.05／1.30／1.60秒を維持する。大型イベントだけ2.40秒とする。

### 3.2 発見・図鑑・表示

- 未発見種は、光へ一瞬入った時点では図鑑へ保存しない。識別完了時に初めて発見と観測回数を同時保存する。
- 未発見ターゲットのレールは種名を伏せて `未同定 / <日本語カテゴリ>` と表示する。既発見種は表示名を出してよい。
- 識別完了時、潜航前の図鑑に存在しなかった種だけ `NEW! / <display name>` を表示する。既知種は `SCAN COMPLETE / +<score>` とする。
- 物理接触だけでは発見、図鑑保存、得点、燃料変化を発生させない。
- 生物の周囲へ円、リング、ハロー、名前ラベルを描かない。

### 3.3 光の見た目

- 外側の淡い円錐、内側の狭い円錐、中心線の3層でサーチライトを描く。既存の艇→対象ソナー線は廃止する。
- 基準色は暖色 `0xF1D58A`。outer alphaは0.05以下、innerは0.08以下、中心線は0.30以下とし、HUDを白飛びさせない。
- 未照射の通常生物はalpha 0.48〜0.68、照射中は0.96まで滑らかに明るくする。色や形は変更しない。
- reduced-motionでは角度補間と明滅を即時・固定表示へ置き換えるが、円錐と識別状態は残す。

## 4. 深度4章

既存hazard band境界を章境界として再利用する。章は背景色、アクセント、粒子、生物重み、専用名を持つ。

| 章 | 深度 | 表示名 | 英語名 | 背景基準 | 強調カテゴリ |
| --- | ---: | --- | --- | --- | --- |
| I | 0〜999m | 薄明境界 | TWILIGHT EDGE | `#0D3440` | fish 1.25、gelatinous 1.15 |
| II | 1,000〜2,499m | 無光層 | MIDNIGHT COLUMN | `#092632` | squid 1.35、gelatinous 1.20、octopus 1.10 |
| III | 2,500〜3,999m | 深淵平原 | ABYSSAL PLAIN | `#061923` | crab 1.35、shrimp 1.25、octopus 1.20 |
| IV | 4,000〜6,000m | 超深海裂溝 | HADAL TRENCH | `#030B12` | other_invertebrate 1.45、octopus 1.30、shrimp 1.20 |

- 強調カテゴリ以外の重みは1.0とする。カタログの実深度範囲を先に満たした候補だけへ章重みを掛け、深度根拠を破らない。
- 章Iは疎らで明るい粒子、章IIは生物発光色の微粒子、章IIIは遅い沈降物、章IVは粒子を減らして暗さと圧力感を出す。
- 章が変わると0.75秒で背景とアクセントを遷移する。ゲーム進行は止めない。
- 初回開始と章境界で1.4秒の帯を表示し、`CHAPTER II / 無光層 / 1000–2499m` のように章番号、名称、深度を同時に伝える。
- HUDの`ZONE`表記は`CH`へ変更し、右下状態へ現在の章名を表示する。
- hazardの数値、回復、6,000m目標はV2を維持する。

## 5. 生物カテゴリ別行動

カテゴリごとの基礎経路と時間変調は決定的に生成し、同じ種・spawn ordinal・時刻なら同じ位置を返す。

| category | 主経路 | 見分けられる行動 |
| --- | --- | --- |
| fish | 左右横断 | 一定速で泳ぎ、上下に小さく蛇行する |
| gelatinous_plankton | 下→上中心 | ゆっくり浮上し、左右へ大きく漂い、明るさが緩く脈動する |
| squid | 左右または斜め横断 | 加速と滑走を周期的に繰り返す |
| octopus | 下層の左右移動 | 遅い這行と短い停止を繰り返し、上下動を小さくする |
| crab | 画面下側の左右移動 | 低速のストップ＆ゴーで底を這う |
| shrimp | 左右横断 | 高速で細かくジグザグする |
| other_invertebrate | 縦移動またはほぼ定点 | ごく遅く漂い、小さく揺れる |

- 行動差は座標、速度、alpha／scaleの軽い変化だけで表現し、画像生成や新規素材を使わない。
- 見た目の揺れは当たり判定を拡大しない。識別判定は表示中心を使う。
- categoryだけで完全固定せず、source catalog IDとordinalを位相へ使い、同カテゴリ内の同期を防ぐ。

## 6. 大型生物イベント

### 6.1 対象と発生

- 既存カタログと既存固有ピクセルアイコンだけを使い、`I021 Architeuthis dux`（ダイオウイカ）と`I022 Mesonychoteuthis hamiltoni`（ダイオウホウズキイカ）を候補とする。クジラは現カタログに存在しないため本スライスへ捏造追加しない。
- 1潜航につき最大1回。深度1,250mで巨大反応を予告し、1,350mで登場、8.5秒で横断する。
- 未発見の候補を優先し、両方既知ならdiveCountの偶奇で交互に選ぶ。候補2種は通常species spawnから除外し、イベント中は新しい通常生物spawnを見送る。

### 6.2 演出とルール

- `MASSIVE CONTACT`、予測進路線、低い画面振動、背景の短い減光の順で予告する。reduced-motionでは振動を省く。
- 予測進路は論理座標の艇初期中心線（`GAME_HEIGHT / 2`）を通す。正面0度の光でも大型個体が射程と円錐内に約4秒残り、必要2.40秒を満たせることを保証する。艇を移動した場合はLIGHTで進路へ照準を合わせる。
- 固有アイコンを2.6〜3.0倍で表示し、通常生物より奥のレイヤーをゆっくり横切らせる。未照射時は巨大な影、照射時は本来の色を見せる。
- 大型個体も右スティックで照らし続けて識別する。必要時間2.40秒、完了スコア300。未発見なら通常どおりNEWと図鑑保存を行う。
- 大型イベントがactiveの間は、光円錐内の大型個体を識別の最優先対象とする。イベント前から残る通常生物は表示と移動を続けるが、大型個体が照射範囲にいる間は通常生物へ識別フォーカスを移さない。これは8.5秒の一度きりのイベントを既存個体に妨害させないための例外である。
- イベント個体との接触は1回だけ燃料-20、clean streakを0へ戻し、赤フラッシュと`MASSIVE IMPACT`を出す。イベントは接触後も通過を続ける。
- 識別できず通過した場合は`CONTACT LOST`を表示するだけで、追加ペナルティはない。
- 大型生物の周囲にも円、リング、ハローを描かない。

## 7. UI優先順位・公平性

- 画面下は左MOVEスティック、右LIGHTスティックを左右対称に置き、中央を空ける。320px幅でも各112px以上の操作領域を残す。
- SCANレールは`IDENTIFY`へ変更してよい。HUD、レール、イベント帯、章帯は互いに重ねない。
- 表示優先度は大型イベント > 章遷移 > 衝突／危険 > 通常識別とする。低優先度表示が高優先度表示を同フレームで上書きしない。
- ライト操作中も左スティック、pause、audioを同時に利用できる。
- サーチライトは燃料を消費せず、ON/OFFや別バッテリーを追加しない。

## 8. 技術責務

- `searchlightRules.ts`: 角度、補間、円錐内判定、ターゲット順位。
- `chapterRules.ts`: 章境界、表示名、配色、カテゴリ重み。
- `speciesBehaviorRules.ts`または既存`speciesRules.ts`: category別の決定的行動。
- `largeCreatureEventRules.ts`: 発生窓、候補選択、状態遷移、得点／衝突不変条件。
- `GameScene`: Phaser描画、二本目スティック、各純粋規則の統合、DOM更新、cleanup。
- 既存カタログJSON、写真manifest、写真asset、149種固有アイコンは変更しない。

- 右スティックで360度照射でき、離しても角度を保持し、ライフサイクルcleanupで入力が残らない。
- 4章の境界、名称、背景、章帯、カテゴリ重みが決定的に変わる。
- 7カテゴリが表の行動差を持ち、全位置計算が有限かつ再現可能である。
- 1潜航に大型イベントは0〜1回で、通常spawnと区別でき、照射識別・見逃し・1回だけの衝突が成立する。
- 左右スティックは衝突揺れの対象外で、320 × 568、390 × 844、430 × 932で重ならない。
- 既存149種、図鑑、写真4点、出典、ライセンス保留状態を壊さない。
- typecheck、全テスト、asset check、production build、git diff --checkが成功する。
- Ultraの実触・スクリーンショット評価に合格後、GitHub Pagesへ公開する。
